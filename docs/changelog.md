## 0.13.7 黑话解释失败后继续原对话

修复批量解释中某个词返回无效格式或调用失败就提前另开对话的问题。所有解释入口共用当前账号的会话，失败、重启或切换解释方式都保留编号，达到配置词数才新建；每次提交的词语尝试（含失败）计数。继续前检查持久化会话：已存在则恢复，仅明确不存在时以原编号创建；读取失败、损坏或归属不符不会变成新对话。旧词输出仍不能作为本轮结果，解释仍需用户确认。

验证：语法检查、客户端冒烟与 157 项测试在本机和服务器通过。服务器独立目录实际调用 DSH 解释 4 个词，在首轮已保存后模拟解析失败并重新加载任务，上限设为 3；实际日志只有两个会话，前 3 轮使用同一编号，第 4 轮才新建，无工具调用。覆盖首次启动未建会话、读日志失败、归属不符及批量失败后的继续处理。

## 0.13.6 修复实际会话复用并解除批量 20 词限制

修复 0.13.3 的会话复用未实际生效：DSH 补丁中的 `name` 是身份校验，不是替换模块，旧配置因此被跳过。现在明确停用默认处理器并插入黑话处理器，修正 Agent 初始化回调返回值，兼容新旧 Session 事件读取接口，校验保存回执与实际会话 ID；旧版未经核实的会话状态会重新开始。

勾选解释支持全部所选待确认词（最多 500 个），全选本页后不再因超过 20 个而禁用；自动批量入口处理所有未完成解释的词，界面显示确切数量。单次批量任务的词数与每个对话的容量分别计算，按配置上限换新对话；已认可和不使用的词仍受保护。

验证：语法检查、155 项 Node 测试与客户端冒烟通过。真实 React + Chromium 验证全选一页提交 50 个词、自动批量提交 75 个词；本机实际 DSH 模型在独立测试目录解释 3 个词，每对话上限设为 2，跨重新加载复用。解压实际会话日志核对恰有两个会话、分别包含 2 轮与 1 轮真实用户请求和完成事件，无工具调用。未执行论坛发送测试。

## 0.13.5 黑话页面使用直白说明

黑话页面改用「从帖子里找新黑话」「让 AI 批量解释」「解释我勾选的词」「认可所选解释并保存」等按钮名称；分类改为「待你确认 / 已认可 / 不使用」。补充操作顺序、自动挑词与勾选解释的区别、每批最多 20 个及按钮暂不可用的原因，说明已解释的词仍需认可。只修改展示文字，不改变提取、解释、确认和保存逻辑。

## 0.13.3 黑话释义对话复用

新增「每个对话最多解析词数」（`slangSessionTerms`，默认 20，范围 1–100）。DSH 黑话释义 / 联网研究按账号跨批次复用专用对话，达到上限后新建，计数持久化并支持重启延续；设为 1 保持每词新建。研究方式切换、生成失败或中断时提前新建，第三方直连仍不创建 DSH 对话，候选提取保持独立。

专用驱动使用宿主 Agent create / resume 与持久化接口，保留工具禁用保护，只读取当前轮输出，避免将旧词释义当成新词结果。所有释义依然作为待确认草稿。

验证：语法检查、148 项 Node 测试和客户端冒烟通过，覆盖跨批次与重启续用、上限边界、账号隔离、配置调整、失败换新、第三方不建对话以及只读取当前轮结果。真实 React + Chromium 验证设置保存；当时服务器模型连续解析两个词的验证只核对了传入的 resume 状态，没有核对实际保存的会话，因此未发现配置被跳过；此验证遗漏与复用问题由 0.13.6 修正。未进行论坛发送测试。

## 0.13.2 回复尝试上限

新增 `replyMaxAttempts`（默认 5，范围 1–100），在「互动 → 回复来信 → 单条来信最多尝试次数」配置。每条来信的查找、生成、发送作为一次处理尝试，开始前持久化次数；默认首次加最多 4 次重试。达到上限仍未完成时写入 `exhausted` 终态并移出待回复队列，保留最终正文（如有）、平台回执、累计次数与最近失败原因，界面显示「已达尝试上限，停止自动回复」。

升级时沿用旧队列次数，已超过上限的来信停止，不再继续查详情、调模型或发送；不会占用新来信的每轮处理名额。终态参与消息去重，重启、重新开启自动回复或提高上限均不自动恢复；降低上限对未终止的旧队列立即生效。未知发送结果保留待确认，不自动重发；成功、已受理和模型跳过不标记为重试耗尽。

验证：语法检查、143 项 Node 测试及客户端冒烟通过，覆盖缺失评论关系、不可访问帖子、生成失败、明确拒绝、旧队列迁移、重启去重、调整上限和未知发送结果。真实 React + Chromium 模拟宿主验证设置保存、停止状态与失败原因显示，桌面及 390px 深色界面无横向溢出或脚本错误；未进行真实账号发送测试。

## 0.13.1 当前模型释义与搜索错误定位

新增「释义研究方式」：默认「当前模型解析」，直接使用高级设置所选的 DSH / 第三方模型，根据原文与已有知识生成草稿，不要求 DeepSeek 官方搜索凭据，并明确标记「模型解析，未联网」。原有联网模式保留，只有主动选择并保存「联网检索核对」后才调用搜索服务；聊天模型的第三方配置不自动授予搜索能力，两种草稿均需人工确认。

搜索失败现在保存阶段与稳定错误码，区分缺少搜索凭据（WEB_PROVIDER_CREDENTIAL_MISSING）、搜索服务不可用、超时、无结果、模型生成失败及引用无效，显示具体处理方式；不记录原始上游响应或凭据。解决此前所有失败都显示同一句笼统提示的问题。缺少搜索凭据时直接提示相应配置项，避免与提取或模型生成错误混淆。

验证：语法检查、136 项 Node 测试和客户端冒烟通过；DSH / 第三方 API 的语境释义解析、搜索凭据错误诊断、引用隔离与待确认状态均已覆盖。真实 React + Chromium 模拟宿主验证当前模型解析、联网模式切换、确认与批量操作，桌面及窄屏深色无溢出或脚本错误。

## 0.13.0 黑话候选、联网研究与确认词库

新增「黑话」Tab，按「提取候选 → 联网研究 → 编辑 / 人工确认 → 回复参考」积累社区用语、梗、反话和特殊指代。候选允许不知道含义，保留实际出现的原文及来源编号；排除普通词、人名、占位和系统报错。自动提取默认关闭，也可从最近保留的 10 份语境手动提取，最近 200 个相同语境去重。

宿主通过 DSH 已配置的 `web.search` 搜索服务检索，由所选 DSH / 第三方模型整理释义草稿，保存实际检索来源；引用必须来自本次结果。候选、已确认、已拒绝分类支持搜索、分页、批量研究（每次最多 20 个候选）、批量确认有含义条目、拒绝及删除。词库最多 500 条，按账号持久化。

只有人工确认的释义用于评论、回复和发帖。发帖结合主题、已选分区和话题检索最多 20 条相关释义，按语境少量自然使用；共用「发帖与回复时参考黑话词库」开关。研究、模型报错或中断都不会自动确认，缺少释义不能确认；人工修改与拒绝不被自动学习覆盖。普通生成仍禁止模型工具；联网搜索由宿主执行，不传小黑盒凭据，不发送评论。DSH 未配置搜索服务时明确显示失败。

改进富文本 / 结构化正文提取、HTML 实体和段落处理；帖子评论增加讨论上下文，父评论缺失时补入本地已发送正文。保留原任务配置，不会自动启用学习、研究或发送。

验证：语法检查、133 项 Node 测试及客户端冒烟测试通过，新增发帖释义检索、确认状态与账号过滤、开关、重启重试和 AI 选区语境覆盖；真实 React + Chromium 使用模拟宿主验证研究草稿、确认、手动添加、批量拒绝、搜索和设置保存，1100px 桌面与 390px 深色布局无横向溢出或脚本错误，打包包含新模块。搜索提供方与模型采用模拟结果验证调用链，未进行真实搜索服务或账号发送联调。

## 0.12.6 旧分区配置兼容

加载旧配置时保留结构校验，不因历史手动分区组合中包含盒友杂谈而停止整个自动化服务。AI 模式不使用旧手动目标；手动任务在提交前检查组合并显示明确原因，仍不会向平台提交冲突分区。

## 0.12.5 发帖分区互斥与平台错误详情

真实发布测试发现平台明确要求「盒友杂谈」分区只能单独选择。增加手动设置、AI 选择结果的校验和模型选择提示，避免与其他分区组合提交；界面在添加冲突分区时显示原因。

发帖被拒绝或结果未知时，保存脱敏后的 HTTP 状态、平台状态与错误说明，并在发帖记录中展示。保留不自动重发的行为，避免重复发布。历史拒绝记录无法凭空恢复平台回执。

## 0.12.4 更多发帖分区与可选话题

留空查询时合并编辑器推荐、已关注、近期热门及可用分类分区，按社区 ID 去重，手动与 AI 自动选择均使用扩展候选。社区列表暂时不可用时保留编辑器推荐并提示重试；仍可按名称搜索其他分区，候选不代表平台完整目录或账号发帖权限。

界面明确说明话题选填，可只选分区发帖，查询后显示分区数量。增加手动与 AI 模式不带话题发布的回归测试，保留原有选择数量与活动话题限制。

## 0.12.3 长发帖角色卡

发帖人格的输入框与保存校验上限从 2000 提高到 20000 字符，支持粘贴长篇多行角色卡；输入区加高并显示当前字符数及上限。超限保存返回明确长度提示。角色卡原文完整保存，并用于发帖时间规划、AI 选区、正文生成及选择沿用发帖人格的自己帖子回复。已有配置保留，其他人格与提示词的限制不变。

## 0.12.2 AI 自动选择分区与话题

「发帖 → 发帖分区与话题」新增「AI 自动选择」模式。到期先读取平台推荐或指定搜索词的候选，再由配置的模型结合写作主题、独立发帖人格和选择偏好，选择 1–2 个分区与 0–5 个话题，活动话题最多 1 个；随后按选定目标生成正文。没有合适分区时跳过，候选外 ID 与话题被宿主拒绝，不回退到手动目标。

选择模式、搜索词和偏好随任务保存，选定目标在正文失败或重启后沿用，并展示在发帖记录中。默认仍为手动模式，升级不会自动发帖。DSH 与第三方 API 均复用同一发帖人格和校验。通过模拟接口、模型输出与桌面 / 手机界面检查，真实账号公开发布仍待验收。详见 [AI 自动选择](configuration.md#ai-自动选择分区与话题0122)。

## 0.12.1 回复自己帖子的评论

「互动 → 回复来信」新增「自动回复自己帖子的评论」开关，需要同时开启「自动回复评论」。核实当前账号是帖子作者后，回复其他用户直接发表的顶层评论；适用于插件发布和手动发布的帖子。自己评论和其他用户之间的对话会被过滤；后续明确回复当前账号的来信仍走原自动回复流程。

可选择使用回复人格，或沿用发帖人格：后者优先取该帖发帖记录中的人格，没有记录则取当前发帖人格。记录显示回复对象类型与人格来源。复用现有消息检查频率、持久化队列、额度、冷却、失败重试和发送去重；默认关闭，升级不主动扩大发言范围。依赖平台消息通知，不会扫描自己所有历史帖；真实账号的通知字段与公开回复仍待验收。

## 0.12.0 提示词控制发帖时间

「发帖 → 发帖时间方式」新增「提示词规划时间」。例如填写“每天在午休或晚间选择 1–2 个不固定时间，周日不发”，并设置每日上限及最短间隔。宿主首次开启和每天跨天后，让模型规划当天剩余时间，保存后到点再生成正文并发布；时间规划和正文生成都使用高级设置中的模型及独立发帖人格。正常每天规划一次，宿主每 5 秒检查本地时间，不会反复请求模型。保留原固定时间模式，升级不会自动切换或开启。

「时间规划记录」可查看安排、未安排、失败和重试状态。计划按账号持久化，重启沿用；修改时间提示词从下一天生效，降低每日上限或增大间隔会约束剩余任务。无效计划最多尝试 3 次，间隔至少 5 分钟，当日失败后不发帖。模型允许选择当天不发；自然语言条件由模型理解，宿主强制校验数量、未来时间和最短间隔。详见 [提示词时间规划](configuration.md#提示词时间规划0120)。

## 0.11.1 发帖分区与话题

「设置 → 刷小黑盒 → 发帖 → 发帖分区与话题」支持登录后按名称搜索、选择和移除目标。最多选择 2 个分区、5 个话题，其中活动话题最多 1 个；搜索词留空可读取平台推荐。选择完成后点击保存，定时发帖会提交所选分区与话题，并在生成时参考它们，继续遵守独立发帖人格。

## 0.11.0 独立人格定时发帖

新增「发帖」Tab，可单独设置发帖人格、主题、社区 ID、时区和单次 / 每天 / 每周发布时间。使用高级设置中的模型来源，到期生成文字帖子并提交；发帖人格不继承评论或回复人格。默认关闭，升级不会自动发帖。

## 0.10.9 每日额度上限

每日评论与每日回复额度均支持 0–9999，默认仍各为 10，升级保留已设额度。额度按发送尝试统计，仍遵守发送冷却、调度与平台限制。

## 0.10.8 深层评论查找修复

修复来信位于楼中楼第 6 页及以后时反复提示「暂未找到完整评论关系」的问题。每轮仍最多查 5 页，但分页进度保存到待回复队列，下轮从上次位置继续，重启也保留进度；查到底仍未找到时重置，后续可重新查找。回复前仍核对评论归属，不保证已删除或不可访问的评论能够回复。

## 0.10.7 自定义提及兼容

核对旧补丁脚本的小黑盒功能：评论 / 回复创建所需的 Workshop v15 `_rnd` 签名及新版参数已内置，无需额外打补丁。新增「互动 → 评论帖子 → 缺少 ID 时允许纯文本 @」，默认关闭；开启后，自定义用户未填 ID 时可以发送普通 `@昵称`，避免旧配置阻断该条评论。纯文本不绑定用户，不能保证通知到对方；填写 ID 时仍优先生成用户链接。该选项仅影响帖子评论，不影响按评论 ID 定位的回复。

## 0.10.6 待回复队列

发现的待回复来信先按账号保存在本地 `automation.json`。例如收到 10 条、每轮限制 5 条，剩余 5 条留到下轮；生成失败、暂时取不到完整评论关系或平台明确拒绝发送时也保留，下轮按设置继续。重启、来信变为已读或不再出现在消息列表中，不会清除已经入队的记录。「评论记录」新增队列，显示尝试次数、最近原因和待确认状态。

重试仍受开关、每日额度、冷却和运行时段限制，每次实际发送尝试都占每日额度；额度耗尽保留到次日。发送结果未知时保留为待确认，请先到平台核对，不自动重发；已发送、已受理、模型决定跳过或确认并非回复自己的评论时结束处理。旧版未入队的拒绝记录不会批量补发。详细行为见 [失败与积压回复队列](configuration.md#失败与积压回复队列0106)。

## 0.10.5 评论发送修复

修复 [Issue #1](https://github.com/fbbDirge/dsh-xiaoheihe/issues/1)：评论和回复的创建请求使用新版网页参数及 `_rnd` 附加签名，解决旧请求可能被返回“缺失参数”的问题。浏览接口不变。平台失败响应的 HTTP 状态、业务状态与原因经敏感信息过滤后保存在评论记录中，便于排查。

该版本产生的拒绝或发送结果未知记录继续去重，升级不会自动补发。0.10.6 起新入队回复的明确拒绝会重试，结果未知仍不自动重发。新增请求构造与错误处理测试均为离线模拟；提交者报告新版参数可真实发送，维护者尚未完成独立真实账号复验，不代表已验证 @ 通知。
